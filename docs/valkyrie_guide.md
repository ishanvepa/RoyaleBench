# Valkyrie quick guide

Valkyrie is Vals AI's platform for running agent evaluations. For RoyaleBench, it connects our versioned Clash Royale task dataset, an agent harness, a frontier model, and Modal compute, then exposes results and traces. This supports the Build Your Own Eval goal: demonstrate meaningful model failures with reproducible scores and concrete examples for the November 14–15 hackathon.

## What we build and what each platform does

| Component | Role in RoyaleBench |
| --- | --- |
| Our Harbor tasks | Define the instructions, environment, inputs, and verifier that awards a score. |
| Agent harness + model | Attempt each task; the harness gives the model tools and controls its execution. |
| Valkyrie | Publishes datasets, starts and tracks evaluation runs, and provides results and artifacts. |
| Modal | Supplies the sandbox compute used by those runs; see the [Modal guide](modal_guide.md). |

Package tasks in the [Harbor format](https://docs.harborframework.com/tasks/overview): `instruction.md`, `task.toml`, `environment/`, `tests/test.sh`, and an optional reference solution in `solution/`. The verifier writes its numerical reward to `/logs/verifier/reward.txt` or `/logs/verifier/reward.json`. Our responsibility is to make that reward measure strategic task performance reliably.

## Set up

```bash
uv tool install valkyrie-cli
# Only if not already signed in:
valkyrie login
valkyrie org use hackathon-rip-ojas-e8d933c926
```

Use the existing team organization. Modal is configured once for the organization;
check `valkyrie provider list` before following the [Modal guide](modal_guide.md).

Choose your own Anthropic secret name in each terminal session. Ben uses
`anthropic-api-key-ben`; Ishan uses `anthropic-api-key-ishan`. Set the variable to
your name (the example below is for Ben):

```bash
export VALKYRIE_ANTHROPIC_SECRET="anthropic-api-key-ben"
```

This variable holds the secret's name, not the API key. If your secret does not
already exist, save your key once at the hidden prompt:

```bash
valkyrie secret set "${VALKYRIE_ANTHROPIC_SECRET:?Set your secret name first}"
```

Secrets are shared across the organization. The suffix identifies whose API
account pays; it does not restrict access to that person. Each run explicitly
selects its secret, so teammates can use different keys without replacing one
another's. `valkyrie secret set` replaces an existing value; skip it when your
key is already saved.

The example below uses the harness and dataset recorded as prepared in the [smoke-test guide](valkyrie_smoke.md). That guide also covers republishing the smoke task.

## Run one task first

```bash
valkyrie run start \
  --agent claude_code-v1.0.0 \
  --dataset royalebench/smoke@1 \
  --model anthropic/claude-sonnet-4-6 \
  --provider modal \
  -s ANTHROPIC_API_KEY "${VALKYRIE_ANTHROPIC_SECRET:?Set your secret name first}" \
  --slice 0:1 --concurrency 1 \
  --label royalebench-connection-smoke --connect
```

Save the printed run ID. Once complete, replace `RUN_ID` below to retrieve the score and traces:

```bash
mkdir -p runs
valkyrie run results RUN_ID --path ./runs/valkyrie-smoke-results.json
valkyrie run artifacts RUN_ID
valkyrie run output RUN_ID --output-dir ./runs/valkyrie-smoke-output
```

The smoke task should receive reward 1. Check the downloaded trace too. Exclude this infrastructure check from reported benchmark difficulty scores. Use `valkyrie tui` to view team runs.

## Publish the benchmark and compare models

The default is **RoyaleBench v3**: use the [v3 guide](royalebench_v3.md) and build with
`uv run python -m cr_arena.build_v3 --jobs 2`. It packages all 11 released continuation scenarios
against Planner with direct coordinate actions in `benchmarks/royalebench-v3`. Publish with
`valkyrie dataset push royalebench/royalebench-v3 ./benchmarks/royalebench-v3 --tag v3`, then run
the returned immutable revision with `--provider modal`. The dashboard prefers v3 for new jobs.
Historical v1 menu tasks, the coordinate pilot and the older full-match dataset below remain separate.

The match tasks under `./benchmarks/clash-royale` are generated by `uv run python -m cr_arena.build_tasks`; see [Match tasks](match_tasks.md) for how they work and how to check them locally. Publish them:

```bash
valkyrie dataset push royalebench/clash-royale ./benchmarks/clash-royale --tag vN
```

Use the immutable revision returned by this command in `--dataset royalebench/clash-royale@REVISION`. Start with one task, inspect its grading and trace, then expand the run. Compare models with the same dataset revision, grading rules, harness configuration, and resource limits. Record the CLI and harness versions, model identifier, run settings, run IDs, scores, and representative failures.

For submission, explain the benchmark and scoring in the README, include frontier-model results and failure examples, and prepare the demo video. The required opening overview paragraph in the README must be entirely human-written. See the [track guide](build_eval_track.md) for requirements.
